# D3. Demo recording guide

A ready-to-use captioned recording with visible mouse movement and click highlights is hosted on the [demo page](https://arushkhasru.github.io/atlas-dispatch/demo.html). It has no audio. The script below is an alternative if you want to record your own narration.

Target length: **2 minutes 45 seconds**, leaving 15 seconds below the assessment limit. Record the actual browser workflow, not slides. Use the live app or a local production preview. Reset the demo before starting; keep the technician strip visible.

| Time      | Action                                                                                                                                                                                                                                                               | Suggested narration                                                                                                                                                                                 |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0:00–0:20 | Show the queue and fixed demo clock. Select R101.                                                                                                                                                                                                                    | “Atlas needs a reliable morning dispatch decision. This desk surfaces an urgent cold-room fault with no owner. The two-hour ownership target is my explicit assumption, not a supplied SLA.”        |
| 0:20–0:45 | Open R104. Show its original message and R101 comparison. Check the confirmation and select **Link to R101**. Open R101 to show the linked follow-up.                                                                                                                | “A follow-up could become a second job. The coordinator confirms the match. Both messages remain visible, and an incorrect link can be undone.”                                                     |
| 0:45–1:10 | Open R107. Point out T3 is still on a job. Check the completion confirmation, then select **Close job & release T3**.                                                                                                                                                | “A customer says the equipment is running, but we do not automatically close the job. After a simulated confirmation, closing it frees T3.”                                                         |
| 1:10–1:40 | Open R101. Select T3, keep or enter **1 October 2026, 10:00**, and select **Assign & set visit**. Open **Prepare a customer update**.                                                                                                                                | “With a time agreed in this simulated scenario, the urgent request now has an owner and a visit. The update uses that recorded plan. It is only a draft; nothing is sent.”                          |
| 1:40–2:10 | Open R105. Show the clarification form and blocked dispatch. Enter `Packaging machine M-04`, choose **Normal**, and note `Synthetic demo call: customer identified M-04; backup machine is operating, no immediate operational impact reported.` Save clarification. | “An awkward intake says only ‘machine not working.’ We cannot safely infer its priority. These are clearly synthetic callback details. Recording them unlocks assignment.”                          |
| 2:10–2:30 | Open R106 and expand its customer update.                                                                                                                                                                                                                            | “Waiting for a part keeps T2 as owner while leaving visit capacity available. The update says the delivery and return visit are unconfirmed; it invents no ETA.”                                    |
| 2:30–2:45 | Reload to show changes persist. Briefly open **Demo guide** or point to the storage label.                                                                                                                                                                           | “This is a local prototype: one active visit per technician, no travel or skill model, no integrations or shared backend. The useful result is one traceable job with a clear owner and next step.” |

If the clarification form takes longer, show its dispatch guard and skip entering the synthetic callback; keep the video under three minutes. R108 is another ambiguous intake and can be shown instead of R105, but do not invent a safety diagnosis from its pressure warning.

Before submission:

- Personalize the narration so you can explain every decision.
- Play the recording through and check readable text, audible narration, and the actual saved assignment.
- Use a video link accessible to a reviewer without requesting access. Verify the link in a signed-out browser.
- Put the working product URL in D1, the accessible repository URL in D2, and the video URL in D3. Paste only the decision prose from `DECISIONS.md` into D4.
- If hosting is unavailable, leave D1 blank as the assessment permits and demonstrate the reproducible local setup. Do not call an unpublished URL live.
